# GitPorter · 项目上传下载

双击 **`start.bat`**，浏览器会自动打开。就三步：**选文件夹 → 选动作 → 确认**。

令牌已经内置好了，打开就是登录状态，不用配置任何东西。

---

## 选文件夹：可以点，也可以直接打字

点「浏览」后弹窗顶部那行路径是**可编辑的输入框**，三种用法：

| 做法 | 效果 |
|---|---|
| 粘贴完整路径 + 回车 | 直接跳到那个文件夹 |
| 输入一半 + `Tab` | 自动补全；唯一结果直接进入，多个结果列成小标签供点选 |
| 输入错路径 + 回车 | 自动跳到最近的、确实存在的上级目录，并提示跳到了哪 |

输入框边框变**黄**表示「你改的路径还没生效」——按回车或点「前往」才真的跳过去。点「就是这个文件夹」时也会自动采用输入框里的路径，不会白输。

从资源管理器「复制文件地址」带回来的双引号会自动去掉，`~` 会展开成用户目录，所以 `"C:\Users\..."`、`~/projects` 这类都能直接用。

---

## 三个动作分别是什么

### ① 上传到 GitHub
把这个文件夹传到云端。

- 云端还没有这个项目 → 自动建一个新仓库，然后把文件推上去
- 已经在云端了 → 把这次的改动追加进去（不会覆盖云端原有的东西）

会自动帮你做这些事：初始化版本库、写 `.gitignore`（根据项目类型自动勾好，`node_modules` 之类不会被传上去）、补一个 `README.md`、记录这次改动、推送。

### ② 替换远程版本
用本地这个文件夹，**强行覆盖**云端的仓库。

云端的旧提交会消失，只剩你现在的内容。只在你确定"云端那份不要了，以本地为准"的时候用。所以按钮默认是灰的，要勾选"我知道云端的旧内容会消失"才亮起来，点下去还会再弹一次确认。

### ③ 拉取到本地
两个模式：

- **下载一个新项目**：从你的仓库列表里选，或者直接填地址，选个保存目录，就把整个项目克隆下来
- **更新当前文件夹**：如果这个文件夹已经绑定云端仓库，把云端最新的内容拉下来

## 界面上的其他信息

选完文件夹后，工具会自动检查并告诉你：

- 有多少个文件、总共多大
- 是不是一个已经绑定仓库的项目（会显示绑定的仓库名）
- 有多少改动还没保存
- 有没有 `node_modules` 这类不该上传的目录
- 有没有超过 20MB 的大文件（GitHub 单个文件上限 100MB，超了推不上去）

底部"执行过程"会实时显示每一步在干什么，出错时会直接说明原因和怎么修。

---

## 做完之后会看到什么

每次操作结束，底部"执行过程"里会**留下一张结果卡**，不会自己消失：

- 日志区标题右边变成绿色 `✓ 上传成功`
- 卡片里写明传到哪儿了、仓库地址
- 两个按钮：**在浏览器打开**（直接看网页）、**复制链接**（发给别人）

出错时反过来：标题变成红色 `✗ 没有成功`，同样留一张红色卡片，写明失败在哪一步、具体原因、能怎么改。**提示不会一闪就没**，可以慢慢看。

想清掉这些记录，点右侧"清空"。下一次点执行时会自动清掉上一轮的结果卡，不会越堆越多。

## 仓库名怎么填

- 可以用**中文**、字母、数字、`-` `.` `_`
- 空格会自动变成 `-`（`提示词 库` → `提示词-库`）
- `~ ^ : ? * [ ] \ / | " ' < > # % { } `` ` `` 这些符号会自动去掉，不用你记
- 不填会沿用文件夹名

如果提示"仓库名已存在"，说明你账号下已经有同名仓库，**换个名**，或者选「替换远程版本」直接推到那个旧仓库。

---

## 出问题怎么查

每次操作都会在 `~/.gitporter/activity.log` 里留一行记录（开始、成功、失败及原因，带时间）。上传了却没看到项目时，打开这个文件看最后几行就知道卡在哪。

---

## 关于令牌

令牌存在 `~/.gitporter/config.json`，用本机指纹派生的密钥做了 AES-256-GCM 加密，不是明文。

推送时令牌是通过 `http.extraheader` 临时注入的，**不会写进项目里的 `.git/config`** —— 不然你把项目分享给别人，令牌就一起泄露出去了。

想换账号：右上角「设置」→ 粘贴新的令牌 → 保存。

## 常见问题

**Q：提示"还没有连接 GitHub"**
点右上角「设置」重新粘贴令牌。生成地址：GitHub → Settings → Developer settings → Personal access tokens (classic)，勾选 `repo` 权限。

**Q：上传失败说认证错误**
令牌过期或权限不够，重新生成一个。

**Q：大文件传不上去**
GitHub 单文件上限 100MB。选文件夹时如果检测到超过 20MB 的文件，界面会标红提醒，先把它移出去或者加进忽略规则。

**Q：替换之后云端的历史真的没了？**
是的，这是强制覆盖。如果你可能后悔，先别用这个功能，用 ① 上传。

## 网络不通时会自动换条路

GitHub 有两种上传通道：

1. **git 协议**（`github.com`）—— 正常走这个，最快
2. **GitHub 接口**（`api.github.com`）—— git 通道被墙、被代理拦、或者大仓库传到一半断掉时，自动切到这个

第二个通道不需要 git，逐个文件走 HTTPS 接口提交，能穿过去的就是它。代价是慢一些（每 50 个文件报一次进度），但对 1000 个文件以内的项目完全够用。

切换是**自动的**：你在日志里会看到一行黄色的

> git 传输通道不通（unable to access），自动改用 GitHub 接口上传…

然后继续往下跑，最后一样是绿色「上传完成 ✓」。**不用你动手，也不用重新点一次。**

> 实测：把 git 的出口堵死（代理指向一个不存在的端口），7 个文件的项目照样传上去了，云端提交记录对得上。
